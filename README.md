# IP Lead Scout

这个 Skill 的核心设计是：**每一条线索都必须附带可点击的公开证据链接和事件日期**；已签约交易归入背景情报，避免销售把已经结束的交易当成新线索跟进。

`ip-lead-scout` 是一个 Codex Skill，用公开、可核验的信号寻找知识产权（IP）服务的 B2B 潜在客户。它覆盖高校与科研机构、金融与保险公司，以及正在建立 IP 业务的综合性律所。每条候选线索都附具体事件和公开证据链接，并将事实与服务切入点的推断分开。

当前版本：**v0.1.0**。更新记录见 [CHANGELOG.md](CHANGELOG.md)。

## 解决什么问题

技术转移公示、金融产品发布和律所招聘信息分散在不同网站，人工逐一查找、核对日期与判断跟进时机很耗时。仅有机构名单也难以支持销售行动：销售需要知道**发生了什么、证据在哪里、下一步该核实什么**。这个 Skill 将公开信号整理成可追溯的候选线索，同时把已完成交易等背景情报单独列出。

## 安装

将本项目目录复制到 Codex 的 Skills 目录：

```bash
cp -r ip-lead-scout ~/.codex/skills/
```

安装后，`~/.codex/skills/ip-lead-scout/SKILL.md` 应当存在。

向 Codex 提出寻客请求，例如：

## 输出字段

| 字段 | 含义 |
| --- | --- |
| `organization` | 已核实身份的机构 |
| `buyer segment` | 高校与科研机构、金融与保险公司，或正在建立 IP 业务的综合性律所 |
| `specific signal` | 具体公开事件及所处阶段 |
| `event date` | 事件发生日期 |
| `source date` | 证据页面的发布日期 |
| `verification date` | 本次核验该证据的日期 |
| `public evidence URL` | 直接支持该事件的公开页面链接 |
| `IP service angle (inference)` | 与事件对应的潜在服务切入点，明确标注为推断 |
| `next action` | 用于核实机会是否存在的具体跟进动作 |

除逐条线索外，结果还应说明搜索地区、时间窗口，以及三个类别各自的合格线索数、检索词和缺口。已完成交易放在独立的背景情报部分，不计入线索数。

## 它不会做什么

- 不编造联系人、邮箱或电话。
- 不从公开信号推断预算、购买意愿或现有服务商。
- 不宣称未经证实的采购时间或决策进度。
- 不把已签约交易、单独的专利授权或已有成熟 IP 业务的律所凑作新线索。

## 如何扩展

工作规则位于 [SKILL.md](SKILL.md)。可以按业务需要增加买家类别及对应的合格信号，调整默认的六个月回溯窗口，或收紧、放宽信号的资格判断规则。修改规则时，保持公开证据、日期分离、事实与推断分离，以及 `lead`／`context` 分类一致。
